01

这是什么项目

先建立整体印象，细节后面几节再展开。

✅ 它做什么

一个 Chrome 扩展（MV3）。界面有两处：侧边栏 + 独立标签页（设置页）。

用户能做的全部事情：存提示词、用文件夹/标签分类、点一下复制到剪贴板。

不做 明确不碰的边界

不往第三方网站注入脚本、不自动填输入框。

不申请任何网站访问权限；不联网、无服务器、无账号。

界面只有中文，不做多语言。

🧱 技术栈（三件事就够记住）

技术用来干嘛
Vue 3所有界面（侧边栏、设置页）
WXT扩展的构建/打包框架，入口在 src/entrypoints/
chrome.storage.local唯一的数据仓库（正式版），相当于扩展自带的本地数据库
02

三个核心功能

整个产品就浓缩成这张图。记住这三个动词，就看懂了 80%。

💡 一个设计取向，解释你看到的所有界面

复制是最高频动作，所以卡片全身可点；编辑/删除藏在角落，删除要点两下（内联确认）防止手滑。

主界面只有「列表」和「编辑」两个视图，不做弹窗、不做抽屉——因为侧边栏很窄，还要兼容独立标签页。

03

架构：四层楼，依赖只往下走

这是本项目最重要的规则。看懂这张图，就知道任何代码「该放哪、不能放哪」。

层目录放什么能依赖
入口src/entrypoints/扩展入口（background、侧边栏、设置页的挂载）ui / infra / domain
表现src/ui/Vue 组件、composables、全局样式domain / infra / shared
基建src/infra/chrome.storage、剪贴板、文件下载、数据清洗domain / shared
领域src/domain/类型定义 + 纯业务规则（增删改查、筛选、导出格式）只有自己
公共src/shared/常量与通用工具（如 timestamp()）只有自己

🚫 三条绝对禁止（机器会自动查）

1. domain/ 里出现 chrome.*、window、document、vue —— 禁止。领域函数必须是纯函数。

2. ui/ 里直接调 chrome.storage.* —— 禁止，必须走 infra/storage.ts。

3. 任何层反向依赖上层 —— 禁止。由 npm run check:arch 解析语法树自动校验。

04

数据怎么流动

两个最高频的场景走一遍：保存一条提示词、复制一条提示词。

📋 复制的路径（最短）

点卡片 → PromptCard.vue 发出 copy 事件 → App.vue 调 infra/clipboard.ts 的 copyText()（带降级方案）→ 成功 → toast「已复制原文」。

🔒 为什么绕这么远

侧边栏、设置页、右键菜单可能同时改同一份数据。所有写入统一走 useLibrary.commit()，在共享 Web Lock 里「读最新 → 改 → 写回」，防止用旧数据覆盖新数据。

06

改前端前，必守的规则

违反任意一条，npm run verify 或代码审查会挂。逐条对照。

  • 颜色/圆角/间距一律用 CSS 变量。不写死色值。变量名以 --pb- 开头，定义在 global.css。例：background: var(--pb-surface)。
  • 组件只负责渲染和转发事件。业务逻辑放 composable（如 useLibrary），状态不放散在组件里。
  • 写数据必须走 useLibrary.commit()。不直接碰 storage；编辑保存要带上打开表单时的原记录，让系统检测冲突。
  • 界面文字用简体中文，注释也用中文；代码标识符用英文。
  • 破坏性操作用内联二次确认（点删除 → 出现「确认删除? 是/否」），不用 window.confirm。
  • 反馈用底部 toast（useToast），不用 alert。
  • 不要在 ui/ 里 import chrome API。需要浏览器能力时，在 infra/ 加一个封装函数再调。
  • 不要把业务逻辑写进 .vue 模板。模板保持声明式；复杂判断抽成函数或 computed。

🎨 设计令牌速查（最常用的一批）

变量含义变量含义
--pb-bg页面底色--pb-accent强调色（暖橘）
--pb-surface卡片底色--pb-danger危险/删除

常用命令

提交前跑最后一条；纯 chrome-local 构建，无需 manifest 审阅。

命令什么时候用
npm run dev开发模式，热更新，自动开 Chrome
npm run build正式本地构建（chrome-local）
npm test领域逻辑与导出格式回归测试
npm run typecheck类型检查
npm run check:arch校验分层依赖方向（防架构犯规）
